# AGENTS.md — Templates

Working rules for humans, editors, and AI agents working in this category
folder. This folder holds reusable project document shapes.

## Folder Mission

Provide consistent, validated starting shapes for recurring project
documents across all kinds of projects.

## Responsibilities

- Maintain one template per recurring document type.
- Keep templates in sync with the repository standards.
- Keep every template under 100 lines.
- Make templates copy-ready for real project use.

## Boundaries

- Templates only; never actual project documents.
- No placeholder content that looks like real data.
- Do not store project-specific material here.
- Do not modify other project categories from here.
- Keep shapes generic across project types.

## Documentation Rules

- Keep template sections consistent across all templates.
- Follow the repository naming conventions strictly.
- Write in plain, clear language.
- Never add completed example content.
- Never add placeholders or generated content.

## YAML Rules

- Use complete front matter in note-shaped templates.
- Status must be draft, active, complete, or archived.
- Use YYYY-MM-DD dates and lowercase tags.
- Match the title to the eventual document name.

## Navigation Rules

- Do not link templates to actual project notes.
- Keep INDEX.md and SUMMARY.md entries in sync.
- Use the README as the entry point for this category.

## Validation Rules

- Run all checks from validation.yaml before finishing.
- Verify naming and line counts.
- Confirm template files stay under 100 lines.
- Confirm no real documents were created by mistake.

## Editing Rules

- Edit templates when the repository standards change.
- Propagate changes to every template at once.
- Keep templates generic and reusable.
- Keep language neutral across project types.

## Recovery Workflow

- Restore lost templates from git history.
- Recreate a template from the repository standards.
- Align drifted templates back to validation.yaml.
- Confirm all templates still match after recovery.

## Common Mistakes

- Writing sample content inside a template.
- Creating real documents while testing a template.
- Diverging structure between templates.
- Using statuses or dates not allowed by validation.yaml.
- Letting a template exceed 100 lines.
- Forgetting to sync templates with rule changes.
