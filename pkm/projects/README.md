# projects/

Knowledge attached to specific personal projects in this repository.

## Purpose

Keep project-scoped knowledge close to the projects that generate it,
while keeping general knowledge reusable and independent.

## Scope

- Learning, decisions, and context tied to one personal project.
- Notes that are only meaningful within a project's lifetime.

## Folder Contents

- One atomic Markdown note per project or project topic.
- Each note registered in the repository INDEX.md.
- One subfolder per category, each with a README.md and AGENTS.md.

## Categories

- [Active](Active/README.md) — projects currently being worked on.
- [Planning](Planning/README.md) — projects being prepared but not started.
- [Completed](Completed/README.md) — projects that have finished.
- [Archived](Archived/README.md) — projects kept for the record.
- [Templates](Templates/README.md) — reusable project document shapes.
- [Resources](Resources/README.md) — reusable material for projects.
- [Roadmaps](Roadmaps/README.md) — project direction and future work.
- [Meetings](Meetings/README.md) — knowledge from project meetings.
- [Decisions](Decisions/README.md) — project decisions and rationale.
- [Retrospectives](Retrospectives/README.md) — lessons from finished work.

## When to use

- When knowledge is only relevant inside a specific project.
- When a project produces context worth preserving for itself.
- When insights are project-bound and not general truths.

## What does NOT belong here

- General knowledge that belongs in knowledge/.
- Unfinished inquiries belonging in research/.
- Raw thoughts better suited to ideas/.
- Content about the software knowledge base or vendor systems.

## Related folders

- knowledge: general lessons extracted after a project ends.
- research: inquiries scoped outside any project.
- ideas: starting points that may become projects.
