# cloud-vs-self-hosted

## Purpose

Compare running software in the cloud against hosting it yourself.

## Context

Software runs somewhere, and the owner must choose who provides that
somewhere. Cloud platforms offer rented, managed infrastructure; self-hosting
means running the software on machines you operate. The choice trades money,
effort, control, and risk.

## Main Notes

- Cloud hosting rents compute, storage, and services from a provider, paying
  for what is used.
- Self-hosting runs software on machines you buy, lease, or keep, and manage
  yourself.
- The cloud shifts effort: the provider handles hardware, power, networking,
  and much of the operations.
- Self-hosting offers control over data, location, cost structure, and
  capacity, but transfers all operational work to the team.
- Cloud costs grow with usage and can surprise at scale; self-hosting has
  high fixed costs but predictable capacity.
- Compliance and data-residency rules sometimes force self-hosting or a
  specific region.
- Cloud provides elasticity: add capacity in minutes; self-hosting needs
  planned capacity.
- Many teams use both: cloud for bursty or managed needs, self-hosting for
  stable or sensitive workloads.
