# design-patterns-overview

## Purpose

Explain what design patterns are and the categories they fall into.

## Context

Software problems recur in the same shapes across projects. Instead of
solving each one from scratch, developers reuse named solutions that are
known to work. Design patterns are these proven, reusable solutions to common
design problems, described with names, structure, and trade-offs.

## Main Notes

- A design pattern is a reusable solution to a recurring design problem, not
  finished code.
- Patterns are named so teams can discuss solutions precisely: "use a
  factory here" means something specific.
- Creational patterns control object creation, such as singleton, factory,
  and builder.
- Structural patterns shape how classes and objects compose, such as adapter,
  facade, and decorator.
- Behavioral patterns manage communication and responsibility between
  objects, such as observer, strategy, and command.
- A pattern must fit the problem; forcing a pattern adds complexity instead
  of removing it.
- Patterns encode experience and shared vocabulary more than new ideas.
- Anti-patterns are the opposite: common bad solutions to recognize and
  avoid.

## References

  Reusable Object-Oriented Software", 1994.
