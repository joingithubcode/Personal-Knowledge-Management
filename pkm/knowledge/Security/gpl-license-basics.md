# gpl-license-basics

## Purpose

Explain the GNU General Public License and the obligations it places on
redistribution.

## Context

Software licenses define what others may do with code. The GPL is a
copyleft license: it grants broad rights to use, study, and modify the
software, but requires that modified or derived works stay under the same
license. This trade shapes whether a team can legally reuse GPL code.

## Main Notes

- The GPL lets anyone run, study, modify, and redistribute the software and
  its source.
- Copyleft is the core: derivative works must also be released under the GPL,
  preserving the same freedoms for later users.
- Distributing a GPL-covered program, whether modified or not, requires
  offering the corresponding source code.
- A work is derivative when it incorporates or builds on GPL code; how
  linking counts depends on the situation and legal reading.
- Combining GPL code with code under incompatible licenses can block
  distribution of the result.
- Using GPL code internally without distributing it generally triggers no
  obligation.
- Selling GPL software is allowed, but the source must still be offered.
- The AGPL extends the same terms to network services, closing a loophole
  where software runs only on a server.
